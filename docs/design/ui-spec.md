# AI 스터디 협업 플랫폼 화면 설계 명세서

> 이 문서는 Claude Code가 제품의 화면 구조와 상호작용을 일관되게 구현할 수 있도록 작성한 UI/UX 기준 문서다.  
> 별도의 디자인 시안이 없을 때 이 문서를 화면 구현의 기준으로 사용한다.

---

## 0. 문서 사용 지침

### 구현 목표

- AI 스터디 협업 플랫폼의 데스크톱 중심 웹 UI를 구현한다.
- 첫 구현 범위는 MVP 1을 중심으로 하되, 이후 기능이 들어갈 자리를 화면 구조에 미리 확보한다.
- 단순 정적 목업이 아니라 주요 화면 전환, 패널 열기, 선택 상태, 빈 상태, 로딩 상태, 오류 상태가 확인되는 프로토타입을 만든다.
- 백엔드가 준비되지 않은 기능은 현실적인 목 데이터와 지연 시간을 사용한다.
- 화면에 보이는 모든 주요 버튼은 최소한 예상되는 UI 반응을 보여야 한다.

### 우선순위

1. 공동 문서 편집 경험
2. 워크스페이스와 페이지 탐색
3. AI 질문 및 문서 수정 제안
4. 멤버 초대와 협업 상태
5. 검색, 버전 기록, 설정
6. 화이트보드, 자료 처리, 개인 AI, MCP 확장

### 제품의 핵심 인상

이 제품은 채팅 서비스가 아니라 **여러 사람이 자료와 문서를 중심으로 학습하고, AI가 그 작업 안에 참여하는 협업 공간**이다.

따라서 화면의 시각적 우선순위는 다음과 같다.

1. 현재 작업 중인 문서 또는 화이트보드
2. 함께 작업하는 사람과 협업 상태
3. AI가 제시한 보조 정보와 수정 제안
4. 페이지 구조와 자료 탐색

AI 채팅이 작업물을 압도하거나 메인 화면 전체를 차지하지 않도록 한다.

## 1. 제품 범위

### MVP 1에서 실제로 상세 설계할 기능

- 로그인
- 워크스페이스 생성 및 진입
- 워크스페이스 멤버 초대
- 페이지 트리
- 공동 문서 생성 및 편집
- 실시간 접속자, 커서, 선택 영역
- 문서 자동 저장 상태
- 댓글
- 기본 문서 스냅샷과 버전 기록
- AI 문서 요약
- AI 질문
- AI 수정 제안
- 수정 전후 비교
- 승인 후 문서 반영

### 화면 구조에 자리만 확보할 기능

- 화이트보드
- 파일 및 링크
- 통합 검색
- 자료 기반 AI 답변과 출처
- 개인 AI 연결
- 원격 MCP 연결
- MCP 실행 승인
- 로컬 브리지
- 자동화

자리만 확보하는 기능도 메뉴나 화면이 완전히 죽어 보이지 않도록 간단한 준비 중 화면 또는 목업 상태를 제공할 수 있다.

## 2. 사용자와 권한

### 워크스페이스 역할

| 역할 | 핵심 권한 |
|---|---|
| OWNER | 모든 설정, 소유권, 멤버 및 콘텐츠 관리 |
| ADMIN | 멤버, 콘텐츠, 일반 워크스페이스 설정 관리 |
| MEMBER | 허용된 콘텐츠 보기, 편집, 댓글, AI 사용 |
| GUEST | 초대받은 리소스 보기 또는 댓글 |

### 자원별 권한

- VIEW
- COMMENT
- EDIT
- MANAGE

### UI 권한 처리 원칙

- 권한이 없는 작업은 가능한 경우 버튼을 숨기지 말고 비활성화하여 이유를 설명한다.
- 클릭 가능한 것처럼 보이지만 아무 반응이 없는 요소를 만들지 않는다.
- 비활성 요소에는 툴팁으로 이유를 제공한다.
- 권한 부족으로 작업이 실패하면 토스트만 보여주지 말고, 해당 UI 주변에도 원인을 표시한다.

예시:

- `이 페이지를 편집할 권한이 없습니다.`
- `워크스페이스 관리자만 멤버를 초대할 수 있습니다.`
- `이 AI 제안은 이미 다른 멤버가 처리했습니다.`

## 3. 디자인 방향

### 키워드

- 차분함
- 집중
- 명료함
- 협업의 온기
- 신뢰할 수 있는 AI
- 과도하게 미래적이지 않음

### 피해야 할 방향

- AI 서비스라는 이유로 보라색 그라데이션을 화면 전반에 과용
- 카드가 지나치게 많은 대시보드
- 모든 요소에 굵은 테두리와 그림자 사용
- 게임처럼 과장된 애니메이션
- 중요한 작업 영역보다 AI 채팅이 더 강하게 보이는 구성
- 데스크톱 생산성 앱에서 불필요하게 큰 여백과 큰 글자 사용

### 기본 테마

- 첫 구현은 라이트 테마
- 다크 테마를 추가하기 쉽도록 컬러 토큰 사용
- 본문 배경은 순백색 또는 아주 옅은 중성색
- 사이드바와 패널은 본문과 미세하게 구분되는 배경 사용

### 컬러 토큰 제안

정확한 색상은 구현 과정에서 조정할 수 있지만 역할은 유지한다.

| 토큰 | 용도 | 제안값 |
|---|---|---|
| `background` | 앱 배경 | `#F7F8FA` |
| `surface` | 작업 영역 | `#FFFFFF` |
| `surface-subtle` | 사이드바, 보조 영역 | `#F4F5F7` |
| `border` | 기본 경계 | `#E2E5E9` |
| `text-primary` | 제목과 본문 | `#20242A` |
| `text-secondary` | 보조 정보 | `#66707C` |
| `text-tertiary` | 플레이스홀더 | `#929AA5` |
| `primary` | 주요 액션 | `#4F67E8` |
| `primary-soft` | 선택 배경 | `#EEF1FF` |
| `success` | 저장 완료, 승인 | `#218A61` |
| `warning` | 주의, 승인 대기 | `#B7791F` |
| `danger` | 삭제, 실패 | `#C94343` |
| `ai` | AI 관련 강조 | `#6756D8` |

### 타이포그래피

- 한글과 영문 가독성이 좋은 산세리프 서체를 사용한다.
- 기본 본문: 14px
- 문서 본문: 16px, 줄 높이 1.7
- 보조 정보: 12~13px
- 화면 제목: 18~24px
- 문서 H1: 30~34px
- 문서 H2: 24~28px
- 버튼과 탭은 지나치게 굵게 만들지 않는다.

### 모서리와 그림자

- 일반 컨트롤: 6~8px
- 카드와 팝오버: 10~12px
- 모달: 12~16px
- 기본 화면 영역 구분은 그림자보다 배경과 1px 경계를 우선한다.
- 그림자는 팝오버, 드롭다운, 모달처럼 떠 있는 요소에만 사용한다.

### 아이콘

- 한 종류의 선형 아이콘 세트를 일관되게 사용한다.
- 기본 크기 16px, 주요 액션 18~20px
- 아이콘만 있는 버튼에는 반드시 툴팁과 접근성 레이블을 제공한다.

## 4. 글로벌 레이아웃

### 데스크톱 기본 구조

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 좌측 사이드바 │                  메인 작업 영역          │ 우측 패널 │
│ 240px         │                    유동                  │ 360px     │
│               │                                          │ 선택적    │
└──────────────────────────────────────────────────────────────────────┘
```

### 너비 기준

- 좌측 사이드바 기본: 240px
- 좌측 사이드바 축소: 56px
- 우측 패널 기본: 360px
- 우측 패널 조절 가능 범위: 320~520px
- 메인 작업 영역 최소 권장 너비: 640px
- 앱 최대 너비는 제한하지 않는다.
- 문서 실제 본문은 메인 영역 안에서 최대 760~840px로 제한한다.

### 세 영역의 책임

#### 좌측 사이드바

- 워크스페이스 전환
- 빠른 검색
- 홈
- 페이지 트리
- 자료실, 활동, 설정 접근
- 새 페이지 생성

#### 메인 작업 영역

- 문서
- 화이트보드
- 파일 미리보기
- 검색 결과
- 설정 화면

#### 우측 패널

- AI
- 댓글
- 문서 정보
- 활동 및 버전

우측 패널은 동시에 하나만 열린다. 상단 탭으로 전환할 수 있으며 닫을 수 있다.

### 반응형 기준

| 구간 | 동작 |
|---|---|
| 1440px 이상 | 3단 구조를 여유 있게 표시 |
| 1100~1439px | 3단 구조 유지, 본문 폭 축소 |
| 768~1099px | 우측 패널은 오버레이 또는 드로어, 좌측은 축소 가능 |
| 767px 이하 | 좌측과 우측 모두 드로어, 메인 작업 영역만 상시 표시 |

모바일에서 MVP 전체 편집 기능을 완벽히 제공할 필요는 없지만, 문서 열람, 간단한 편집, 댓글, AI 질문은 사용할 수 있어야 한다.

## 5. 글로벌 내비게이션

### 좌측 사이드바 상단

1. 워크스페이스 선택 버튼
2. 검색 버튼
3. 홈
4. 알림 또는 받은 편지함

워크스페이스 선택 버튼 구성:

- 워크스페이스 아이콘
- 워크스페이스 이름
- 펼침 화살표

클릭 시 드롭다운:

- 현재 계정 정보
- 최근 워크스페이스 목록
- 워크스페이스 만들기
- 워크스페이스 설정
- 로그아웃

### 페이지 트리

각 행 구성:

- 펼침 화살표
- 타입 아이콘 또는 이모지
- 제목
- 호버 시 더보기 버튼

동작:

- 클릭: 리소스 열기
- 화살표 클릭: 자식 펼치기 또는 접기
- 드래그: 위치 이동
- 우클릭 또는 더보기: 이름 변경, 복제, 이동, 즐겨찾기, 보관
- 제목이 길면 말줄임
- 현재 페이지는 `primary-soft` 배경으로 표시
- 다른 사용자가 해당 페이지를 보고 있으면 작은 아바타 또는 점을 우측에 표시

### 페이지 생성

사이드바 하단 또는 페이지 섹션 제목 옆에 `+`를 제공한다.

클릭 시 작은 생성 메뉴:

- 새 문서
- 새 화이트보드
- 파일 업로드
- 새 폴더
- 링크 추가

MVP에서 구현되지 않은 타입은 `곧 제공` 표시를 할 수 있다.

### 사이드바 하단

- 멤버
- 활동
- 설정
- 도움말
- 현재 사용자 아바타

## 6. 공통 상단 바

리소스 화면의 메인 영역 상단에 48~52px 높이의 고정 바를 둔다.

### 왼쪽

- 모바일 또는 축소 상태의 사이드바 열기 버튼
- 상위 경로 브레드크럼
- 현재 리소스 제목

### 오른쪽

- 저장 상태
- 현재 접속자 아바타 스택
- 공유 버튼
- 댓글 패널 버튼
- AI 패널 버튼
- 더보기

### 저장 상태 표현

- `저장 중…`
- `저장됨`
- `오프라인 — 변경사항을 보관 중`
- `동기화 실패`

저장 완료 상태는 몇 초 후 아이콘 중심의 조용한 표현으로 축소한다. 공동 편집 문서에서 사용자가 직접 저장 버튼을 누르게 하지 않는다.

### 현재 접속자

- 최대 4명까지 겹친 아바타 표시
- 초과 인원은 `+3` 형식
- 클릭 시 현재 접속자 팝오버
- 각 사용자 옆에 현재 상태 표시: `편집 중`, `보고 있음`, `오프라인`

### 공유 버튼

OWNER 또는 ADMIN:

- 멤버 초대
- 링크 접근 정책
- 현재 페이지 권한
- 공유 링크 복사

MEMBER 또는 GUEST:

- 현재 접근 권한 확인
- 공유 링크 복사
- 접근 요청

| SET-03 | MCP 연결 | `/settings/mcp` |
| ACT-01 | 활동 기록 | `/w/:workspaceId/activity` |

## 8. AUTH-01 로그인

### 목적

사용자가 빠르게 인증하고 최근 작업 공간으로 돌아간다.

### 레이아웃

- 화면 중앙의 단일 로그인 패널
- 상단 로고와 제품명
- 짧은 설명: `함께 공부하고, AI와 정리하세요.`
- 과도한 마케팅 영역은 두지 않는다.

### 필드와 액션

- 이메일
- 비밀번호
- 로그인 버튼
- Google 로그인
- 비밀번호 찾기
- 회원가입 이동

### 상태

- 초기
- 필드 검증 오류
- 로그인 진행 중
- 자격 증명 오류
- 네트워크 오류

### 오류 메시지

입력 필드 아래에 구체적으로 표시한다.

- `이메일 형식을 확인해주세요.`
- `이메일 또는 비밀번호가 올바르지 않습니다.`

## 14. AI-02 AI 수정 제안 비교

### 목적

AI가 만든 변경을 사용자가 확인하고 승인한 뒤 공동 문서에 반영한다.

### 핵심 원칙

- AI는 사용자의 승인 없이 기존 문장을 조용히 변경하지 않는다.
- 무엇이 추가, 삭제, 변경되는지 명확히 보인다.
- 전체 승인, 개별 승인, 거절이 가능해야 한다.
- 제안 기준 버전 이후 문서가 바뀌었는지 표시한다.

### 진입 방식

- AI 패널 응답에서 `수정 제안으로 보기`
- 선택 텍스트 툴바의 AI 작업
- AI 제안 알림

### 기본 레이아웃

넓은 화면:

```text
┌────────────────────────────────────────────────────────────┐
│ 제안 제목 / AI 모델 / 생성 시각 / 기준 버전                │
├───────────────────────────┬────────────────────────────────┤
│ 현재 문서                  │ AI 제안                        │
│ 원문                       │ 변경 결과                      │
└───────────────────────────┴────────────────────────────────┘
│ [거절] [나중에]                         [선택 적용] [전체 적용] │
└────────────────────────────────────────────────────────────┘
```

좁은 화면:

- 인라인 Diff
- 원문과 제안을 탭으로 전환

### Diff 표현

- 삭제: 옅은 빨간 배경과 취소선
- 추가: 옅은 초록 배경
- 수정: 삭제와 추가를 나란히 또는 연속 표시
- 블록 단위 변경은 블록 경계 표시

색상만으로 변경 종류를 구분하지 않는다. `삭제`, `추가`, `수정` 레이블을 함께 사용한다.

### 제안 항목

각 operation 카드:

- 대상 블록
- 변경 이유
- Diff
- 승인 체크
- 원문 유지

가능한 동작:

- 이 변경 적용
- 이 변경 제외
- 직접 수정 후 적용
- 해당 위치 문서에서 보기

### 버전 충돌

현재 문서가 AI 제안의 기준 버전과 다르면 상단에 경고:

`제안이 생성된 후 문서가 변경되었습니다. 변경 내용을 현재 문서에 맞춰 다시 확인해주세요.`

동작:

- 현재 버전에 맞추기
- 원래 기준 버전 보기
- 제안 취소

자동 재기준화 후에도 충돌이 남으면 해당 operation만 별도 경고하고 전체 적용을 막는다.

### 적용 완료

- 승인된 변경을 하나의 AI 출처 트랜잭션으로 반영
- 성공 토스트: `AI 제안 3개를 문서에 반영했습니다.`
- 실행 취소 제공
- 활동 기록에 AI 모델, 승인자, 변경 수 기록

## 24. 공통 컴포넌트

### 버튼

종류:

- Primary
- Secondary
- Tertiary/Ghost
- Danger
- Icon

규칙:

- 한 영역에 Primary 버튼을 여러 개 배치하지 않는다.
- 비동기 동작 중 버튼에 진행 상태를 표시하고 중복 클릭을 막는다.
- 단순 닫기는 텍스트 대신 아이콘을 사용할 수 있다.

### 입력

- Label
- Input
- Description
- Error message

레이블을 플레이스홀더로 대체하지 않는다.

### 토스트

용도:

- 저장 완료
- 링크 복사
- 비차단 성공
- 복구 가능한 짧은 오류

중요한 승인, 권한 문제, 데이터 손실 위험은 토스트만으로 처리하지 않는다.

### 모달

- 파괴적 또는 집중이 필요한 작업에만 사용
- 일반 정보나 필터는 팝오버 또는 패널 사용
- Escape 및 바깥 영역 클릭 정책을 일관되게 유지
- 파괴적 확인 모달은 버튼 문구에 행동을 직접 명시

좋은 예:

- `페이지 삭제`
- `멤버 제거`

나쁜 예:

- `확인`

### 드롭다운과 팝오버

- 화면 밖으로 잘리지 않도록 위치 조정
- 키보드 탐색 지원
- 선택 상태 표시
- 위험 작업은 구분선 아래에 배치

### 아바타

- 이미지가 없으면 이름의 첫 글자
- 사용자별 협업 컬러와 아바타 배경은 별개로 관리 가능
- 겹친 아바타에는 경계선을 두어 구분

### 배지

- 상태 정보에만 사용
- 모든 메타데이터를 배지로 만들지 않는다.

### 스켈레톤

- 실제 레이아웃과 유사한 형태
- 로딩 스피너보다 목록과 문서 골격을 우선
- 300ms 이내 완료되는 동작은 스켈레톤을 생략하여 깜빡임을 줄인다.

## 25. 전역 상태 설계

### 반드시 설계할 상태

모든 주요 화면은 다음 상태를 가진다.

1. 정상 데이터
2. 최초 로딩
3. 부분 로딩
4. 빈 상태
5. 오류
6. 권한 없음
7. 오프라인
8. 재연결 및 동기화

### 오프라인

- 상단 저장 상태에 표시
- 사용자의 로컬 편집을 가능하면 유지
- 연결 복구 시 자동 동기화
- 재연결 전에는 AI와 외부 도구 요청 비활성화

메시지:

`오프라인 상태입니다. 문서 변경은 이 기기에 임시 보관됩니다.`

### 세션 만료

편집 내용을 잃지 않도록 현재 상태를 보관한 후 로그인 모달 또는 로그인 화면으로 안내한다.

### 다른 사용자에 의한 변경

- 페이지 이름 변경: 즉시 UI 반영
- 페이지 이동: 사이드바 위치 갱신
- 페이지 보관: 읽기 전용 상태와 안내
- 권한 회수: 편집 중지 및 남은 로컬 변경 처리 안내

## 26. 접근성

- 모든 기능은 가능한 범위에서 키보드로 접근 가능해야 한다.
- 포커스 표시를 제거하지 않는다.
- 아이콘 버튼에는 접근성 이름을 제공한다.
- 폼 오류는 색상뿐 아니라 텍스트로 설명한다.
- 텍스트와 배경은 WCAG AA 대비를 목표로 한다.
- 협업 커서 색상만으로 사용자를 식별하지 않고 이름을 함께 표시한다.
- Diff는 빨강과 초록만으로 구분하지 않고 레이블과 기호를 사용한다.
- 모달이 열리면 포커스를 내부에 가두고 닫힐 때 이전 요소로 돌려준다.
- 애니메이션 감소 환경 설정을 존중한다.
- 드래그 작업에는 메뉴 기반 이동 대안을 제공한다.

## 30. 구현 완료 기준

### 전체

- 모든 주요 라우트가 연결되어 있다.
- 현재 위치가 내비게이션에서 명확하다.
- 데스크톱과 태블릿 너비에서 레이아웃이 깨지지 않는다.
- 주요 비동기 동작에 로딩, 성공, 오류 피드백이 있다.
- 목 데이터가 실제 협업 제품처럼 일관된다.

### 공동 문서

- 페이지 트리에서 문서를 열고 전환할 수 있다.
- 문서 제목과 본문을 편집할 수 있다.
- 블록 추가 메뉴와 선택 툴바가 동작한다.
- 저장, 오프라인, 동기화 상태를 시연할 수 있다.
- 접속자와 다른 사용자 커서가 표현된다.

### AI

- AI 패널을 열고 닫을 수 있다.
- 추천 작업 또는 직접 질문으로 응답을 생성하는 흐름이 있다.
- 컨텍스트 범위를 확인할 수 있다.
- 응답을 문서 변경 제안으로 전환할 수 있다.
- Diff에서 변경별 승인 및 전체 승인이 가능하다.
- 버전 충돌 상태를 시연할 수 있다.

### 댓글과 버전

- 텍스트 또는 블록에 댓글을 연결할 수 있다.

## 32. 최종 화면 원칙 요약

1. 공동 작업물이 화면의 주인공이다.
2. AI는 독립된 채팅 서비스가 아니라 현재 작업을 돕는 보조자다.
3. AI의 기존 콘텐츠 변경은 Diff와 승인 과정을 거친다.
4. 협업 중인 사용자와 저장 상태가 항상 이해 가능해야 한다.
5. 권한, 출처, 변경 이력을 숨기지 않는다.
6. 빈 상태와 오류 상태도 정상 화면만큼 세심하게 설계한다.
7. 이후 화이트보드, 파일, 개인 AI, MCP가 들어와도 글로벌 구조를 다시 만들 필요가 없어야 한다.
